# ATLAS — Documento Completo de Product Definition + Document Driven Development (DDD)

## 1. Visão Geral do Produto

**Nome do sistema:** Atlas
**Conceito:** Guardião dos acessos, inspirado no porteiro dos portões do Olimpo.
**Objetivo:** Centralizar a gestão de acessos a sistemas corporativos, desde a solicitação até a aprovação, provisionamento, auditoria e revogação.

O Atlas será uma plataforma de **IAM (Identity and Access Management)** com foco em:

* governança de acessos
* workflow de aprovação
* trilha de auditoria
* revisão periódica
* segregação de função
* integração com sistemas internos e terceiros

---

## 2. Problema de Negócio

Empresas possuem múltiplos sistemas com processos descentralizados de concessão de acesso.

Principais dores:

* solicitações por e-mail ou chat
* ausência de trilha auditável
* aprovações informais
* acessos órfãos
* demora no provisionamento
* risco de compliance

O Atlas resolve esse problema por meio de um fluxo estruturado ponta a ponta.

---

## 3. Objetivos Funcionais

1. Solicitar acesso a qualquer sistema cadastrado
2. Aprovar ou reprovar por níveis hierárquicos
3. Provisionar acesso manual ou automático
4. Registrar auditoria completa
5. Revisar acessos periodicamente
6. Revogar acessos automaticamente
7. Integrar com AD, LDAP, APIs e SaaS

---

## 4. Personas

### Solicitante

Usuário final que necessita acesso.

### Gestor Aprovador

Responsável por aprovar acessos do time.

### Owner do Sistema

Dono funcional da aplicação.

### Segurança / Compliance

Responsável por auditoria e governança.

### Administrador IAM

Administra catálogo, perfis e regras.

Cadastro de aplicações:

* nome
* URL
* owner
* criticidade
* tipo de autenticação
* integração
* perfis disponíveis

## 5.2 Gestão de Perfis

Exemplo:

* leitura
* operador
* aprovador
* administrador

## 5.3 Solicitação de Acesso

Campos:

* usuário solicitante
* sistema
* perfil
* justificativa
* prazo
* centro de custo

## 5.4 Workflow de Aprovação

Etapas:

1. gestor imediato
2. owner do sistema
3. segurança (opcional)
4. provisionamento

## 5.5 Provisionamento

* manual
* API
* LDAP/AD
* webhook
* RPA

## 5.6 Auditoria

Registro de:

* quem solicitou
* quem aprovou
* data/hora
* IP
* alteração realizada

## 5.7 Recertificação

Campanhas periódicas:

* 30 dias
* 90 dias
* 180 dias
* anual

```text
Solicitação -> Validação -> Aprovação Gestor -> Aprovação Owner -> Provisionamento -> Confirmação -> Auditoria -> Recertificação
```

## 12. User Stories

### US001

Como usuário, quero solicitar acesso a um sistema para executar minhas atividades.

**Critérios de aceite**

* sistema listado no catálogo
* perfil obrigatório
* justificativa obrigatória
* protocolo gerado

### US002

Como gestor, quero aprovar acesso do colaborador.

**Critérios**

* aprovar ou reprovar
* comentário obrigatório na reprovação
* SLA monitorado
